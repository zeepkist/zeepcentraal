# Rust migration evaluation

This is the first executable migration gate, not a replacement for production services.
The existing Bun API, jobs, lobby host, PostGraphile, and deployment remain active.

## Implemented

- Pinned Postrust integration with admin dashboard, Swagger, Scalar, generated REST,
  GraphQL playground, queries, mutations, and WebSocket subscriptions enabled by default.
- Compile-time SQLx/Diesel alternatives behind the same database service boundary.
  Diesel uses its typed DSL for user lookup and parameterized SQL for aggregate/transaction work.
- SQLx and Diesel native migration runners execute the same synthetic SQL fixture on
  separate databases. Each runner rejects the other adapter's database name.
- User lookup, leaderboard aggregation, and record/audit transaction evaluation routes.
- Read-only validation and SHA-256 inventory of all historical Drizzle migrations.
- Rust Zeepnet bit reader/writer with golden vectors generated by the existing TypeScript implementation.
- Database integration, HTTP/GraphQL subscription smoke tests, dual-adapter CI, load generator,
  and Linux process/host memory sampler.

SQLx is a SQL toolkit, not an ORM. Both implementations remain experimental candidates.
SQLx shares the Postrust pool; Diesel opens a separate application pool. Do not select
an adapter based on this small synthetic dataset alone.

## Start the preview on Windows

Run from the repository root with Docker Desktop's Linux engine running:

```powershell
docker compose --env-file NUL -f tools/rust-evaluation/compose.yml up -d --wait
powershell -NoProfile -File tools/rust-evaluation/run.ps1 -Adapter sqlx
```

In a second terminal:

```powershell
powershell -NoProfile -File tools/rust-evaluation/run.ps1 -Adapter diesel
```

The scripts discover Cargo in PATH or the current user's `.cargo/bin`. They use separate
release target directories so both binaries can run simultaneously. No Bun dependency install is needed.

Linux:

```sh
docker compose --env-file /dev/null -f tools/rust-evaluation/compose.yml up -d --wait
bash tools/rust-evaluation/run.sh sqlx
# Separate terminal:
bash tools/rust-evaluation/run.sh diesel
```

The generated API contains only synthetic preview data. Its schema is **not** the
PostGraphile schema. Production JWT/session middleware is not yet ported; the preview
is local-only and rejects foreign Host/Origin headers. UI assets may require network access.

### GraphQL walkthrough

Inspect the schema and run:

```graphql
query {
  level { id name }
  record(order_by: [{time: asc}], limit: 10) { id id_user id_level time }
}
```

In another playground tab, subscribe:

```graphql
subscription {
  record(order_by: [{id: desc}], limit: 1) { id time }
}
```

Create a record through GraphQL or through the application adapter:

```graphql
mutation {
  insert_record(objects: [{id_user: 1, id_level: 1, time: 28.5}]) { affected_rows }
}
```

```powershell
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4310/evaluation/record -ContentType application/json -Body '{"user":1,"level":1,"time":28.25}'
```

Mutations use HTTP; WebSocket schema supports queries and subscriptions only.
This keeps each mutation inside an explicit commit/rollback boundary.

Both changes should update the subscription. Changes to related tables/views also have
a two-second refresh fallback. This is deliberately short for demonstration; keep the
same interval in A/B runs and measure its database cost.

## Validation

```powershell
cargo fmt --all --check
cargo clippy --workspace --all-targets --no-default-features --features db-sqlx -- -D warnings
cargo test --workspace --no-default-features --features db-sqlx
cargo clippy --workspace --all-targets --no-default-features --features db-diesel -- -D warnings
cargo test --workspace --no-default-features --features db-diesel
powershell -NoProfile -File tools/rust-evaluation/test.ps1 -Adapter sqlx
powershell -NoProfile -File tools/rust-evaluation/test.ps1 -Adapter diesel
bun.exe tools/rust-evaluation/binary-fixtures.ts --check
bun.exe tools/rust-evaluation/smoke.ts http://127.0.0.1:4310
bun.exe tools/rust-evaluation/smoke.ts http://127.0.0.1:4311
```

Database tests are explicitly ignored unless requested, not silently passed without a DB.
They need an otherwise unused fixture database and clean up their test records. Smoke
writes are retained for inspection; recreate only these disposable preview containers
when a clean comparison dataset is needed. Do not run database tests concurrently with
smoke writes or manual editing.

Inspect historical migrations without connecting to PostgreSQL:

```sh
cargo run -p zc-migrate -- inspect-history packages/database/drizzle
```

This validates artifacts only. It does not replay historical SQL, adopt its ledger,
prove upgrades work, or replace the production migrator.

## A/B measurement

Use the [controlled Linux benchmark](benchmark/README.md) for repeated Bun/SQLx/Diesel
comparisons with a million-record fixture, idle/active memory sampling, fixed offered
load, and capacity tests. The commands below remain quick read-only smoke measurements.

Keep schema, request count, concurrency, data, cache warmup, preview-feature setting,
telemetry and build profile identical. Alternate A/B order and repeat runs.

```sh
python3 tools/rust-evaluation/measure.py --url http://127.0.0.1:4310 --label sqlx-preview --requests 10000 --concurrency 8 --output artifacts/rust-evaluation/sqlx.json
python3 tools/rust-evaluation/measure.py --url http://127.0.0.1:4311 --label diesel-preview --requests 10000 --concurrency 8 --output artifacts/rust-evaluation/diesel.json
```

On Linux, run the sampler during idle, active, and recovery windows. Pass each relevant
process PID, including child processes. An exited PID invalidates the sample run.

```sh
python3 tools/rust-evaluation/capture_memory.py --pid 1234 --duration 600 --interval 1 --output artifacts/rust-evaluation/sqlx-memory.jsonl
```

Replace the example PID with the server's actual PID. Include PostgreSQL separately;
do not double-count shared pages by summing process RSS. The sampler records PSS,
private memory, MemAvailable, swap and memory pressure. It does not discover new children;
recollect PIDs after restarts and use cgroup measurements for SteamCMD job peaks.

`ZC_PREVIEW_FEATURES=false` (or `run.ps1 -RestOnly`) disables preview surfaces at runtime,
while keeping the same binary features compiled. Defaults: application pool maximum 5,
Postrust pool maximum 5, zero minimum idle connections. `ZC_PREVIEW_POOL_MAX` changes the
Diesel application pool; `ZC_PREVIEW_POSTRUST_POOL_MAX` changes the Postrust/shared SQLx pool.
For equal-budget runs, use SQLx shared=5 versus Diesel application=3 plus Postrust=2.
Also measure intended deployment topology; do not hide the additional Diesel pool cost.

No latency or memory winner is asserted until representative workloads and repeated
measurements exist. Acceptance remains >=50% lower idle median and active p95 memory
against Bun, no higher peak, no correctness errors, and latency/job duration within 5%.

## Remaining gates before production migration

1. Full historical migration replay and upgrade/ledger handover on isolated database copies,
   including pgmq 1.12.0. The synthetic preview intentionally has no pgmq extension.
2. Expand both adapters to real sessions, record/PB transactions, scoring, workshop
   reconciliation, queue leasing/fencing, and tournament preparation.
3. Obtain the seven-day deployed baseline and comparable Linux workload measurements.
4. Prove Rust Steam login, refresh renewal, encrypted tickets and reconnect behavior.
5. Select adapter using correctness, performance, memory and maintenance evidence.
6. Port remaining core/database/telemetry, all jobs/workshop behavior, complete HTTP
   compatibility, then lobby host. Preserve existing TypeScript consumers.
7. User-run private Zeepkist/GTR acceptance, seven-day soak, staged deployment and rollback.

No fake production handlers, no placeholder job consumers, and no old-service cutover
are included in this evaluation gate. PostGraphile replacement remains a later project.
